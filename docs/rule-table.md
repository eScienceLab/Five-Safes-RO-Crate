### Assets

**Operational definition** - An **asset** is either:

* anything that a process touches through `object`/`result`/`instrument`/`prov:used` and that isn't itself a process or a party
* everything under `RootDataEntity` → `hasPart`.

**Note:** Considering the complexity of the asset's operational definition it may be convenient to define it as a class in the `ontology.ttl` of the Five-Safes profile, similarly to what is done for `RootDataEntity` in the RO-Crate base profile.

| Property    | Requirement         | Description                                      | Preconditions                                                                                                   | Comments                                                              |
| ----------- | ------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `@id`     | MAY                 | be a relative IRI.                               | The Asset is a file or directory contained in this RO-Crate and does not require identity beyond this RO-Crate. | The relative IRI identifies the copy in the containing RO-Crate only. |
| `@id`     | MUST                | be an absolute IRI                               | The referenced Asset requires an identity beyond this RO-Crate.                                                 |                                                                       |
| `name`    | SHOULD, exactly one | Names the asset                                  |                                                                                                                 |                                                                       |
| `version` | SHOULD              | reference the version of the asset               | The asset entity refers to a versioned asset (e.g. protocol, software, ...)                                     | Is there a way to check that the pre-condition is met?                |
| `version` | MUST                | be a text                                        | Asset →`version` exists                                                                                     |                                                                       |
| `version` | MUST                | be equal to the label that the asset already has | Asset →`version` exists                                                                                     |                                                                       |
|             |                     |                                                  |                                                                                                                 |                                                                       |

### Plans, Requests, Decisions, Executions, and Associations

**Operational definitions:**

* A **Plan** is an Asset whose `@type` includes `prov:Plan`.
* A **Submission** is an entity whose `@type` includes `AskAction`.
* A **Decision** is an entity whose `@type` is either `AuthorizeAction` or `RejectAction`.
* An **Execution** (attempt) is an entity whose `@type` contains `CreateAction` and `prov:Activity`.
* An **Association** is an entity whose `@type` is `prov:Association`.
